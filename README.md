# Artifact — *Small Models Can Find, But Cannot Write: Where Cloud LLMs Are Needed in SQL Rewriting*

Submitted to **EDBT 2027**, Experiments & Analysis track.

This artifact contains the measurement harness, the query workloads, every execution record behind
the paper, and the scripts that regenerate every figure and table from those records.

**Nothing in the paper is typed by hand.** Each number is produced by a script in `scripts/` reading
a store in `.cache/`. The mapping is in [Where the paper's numbers come from](#where-the-papers-numbers-come-from).

---

## 1. What this is

We measure whether the FIND/WRITE decomposition used by published LLM rewriting systems pays off,
across five configurations of a rewriting agent:

| arm | who finds the strategy | who writes the SQL |
|---|---|---|
| `raw` | one local model (≤8B) | the same local model |
| `aided-local` | local model | a second local model |
| `aided-cloud` | local model | cloud model |
| `ceiling` | cloud model | cloud model |
| `monolithic` | one cloud model | the same cloud model |

`monolithic` is the form that published systems instantiate. We do **not** propose a new optimizer;
we measure the design space that existing ones occupy.

**Scale:** 2,014 runs across 28 documented cells, on TPC-DS (SF20) and JOB/IMDb, on PostgreSQL and
MySQL.

---

## 2. The measurement protocol, in one paragraph

A *run* is one attempt at one query by one configuration. The rewrite is accepted only if it passes
the **S=1 gate**: both the original and the rewritten query are **executed at full scale** and their
result hashes and cardinalities must match. This is execution-based equivalence, **not** an LLM
judge.

**A baseline timeout is not a run.** When the *original* query does not finish within its budget,
no strategy is ever requested and no rewrite is produced. These are counted and reported separately
(**560** of 2,574 attempts, 22%) and never enter any denominator. If you recount our runs, use
`scripts/cell_status.py`, which applies this rule.

## 3. Reproducing one cell

### 3.1 Prerequisites

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # then edit: DB_URI, VERIFY_DB_URI, model settings
```

You also need:

- **Ollama** with the local models pulled. Five act as **finders** — `qwen3:8b`, `llama3.1:8b`,
  `mistral:7b-instruct`, `deepseek-r1:8b`, `deepseek-r1:8b-llama-distill-q4_K_M` — and two act as
  local **writers** in the `aided-local` arm: `qwen2.5-coder:7b` (cell `SL1`) and
  `deepseek-coder:6.7b` (cell `W1`). Cell `W2` uses `qwen3:8b` in the writer role, which is the
  point of that cell;
- the **databases** — see §3.3. They are not shipped: the two TPC-DS SF20 instances plus IMDb are
  roughly **124 GB**.

Start the pipeline server, which reads `.env` **once at startup**:

```bash
.venv/bin/python -m uvicorn src.main:app --port 8000
```

> The server does not re-read `.env`. After changing any configuration, **restart it**, or you
> will measure the previous configuration under the new label.

### 3.2 The cheapest cell — `I1`, about 3 hours, no API cost

`I1` is the `raw` arm on JOB/IMDb with `qwen3:8b`, 13 queries, n=3. It is entirely local, so it
costs nothing but time.

```bash
BENCH=imdb RAWARM=raw bash scripts/campanhas/p1_local.sh qwen 3
```

This writes to `.cache/suggestions_p1_qwen_aided_local_imdb_raw`. Then:

```bash
.venv/bin/python scripts/cell_status.py p1_qwen_aided_local_imdb_raw
```

Our recorded result: **39 real runs over 13 queries, reach 8/13, 1 baseline timeout**, measured
2026-09-16 08:13→11:26. The cell document is
[`documentation/experiments/final/p1/I1__imdb-pg__raw__qwen.md`](documentation/experiments/final/p1/I1__imdb-pg__raw__qwen.md).

**Expect variation.** LLM output is stochastic and we do not fix a seed; reach is a distribution,
not a constant. This is why every comparison in the paper declares its `n`, and why consistency is
only claimed at n=5.

### 3.3 Databases

There is **no provisioning script** in this artifact — the data is generated by standard tooling,
not by us:

- **TPC-DS SF20**, loaded into both PostgreSQL and MySQL, using the official `dsdgen`;
- **IMDb** with the **JOB** schema and queries (Leis et al., *How Good Are Query Optimizers,
  Really?*, PVLDB 2015).

After loading, and **after every switch of `DB_URI`**, run:

```bash
.venv/bin/python scripts/analyze_dbs.py     # both the main and the verification database
```

> Skipping `ANALYZE` fails **silently**, not loudly: the planner goes flat, the original query
> stops finishing, `orig_ms` becomes `None`, the S=1 gate cannot run, and every cell reports zero
> lands. It looks exactly like a bad model. Use `scripts/prep_db.py`, which validates the switch.

## 4. Where the paper's numbers come from

Every artifact below is regenerated from the stores. Run these from the artifact root.

| paper item | command | reads |
|---|---|---|
| **T1** measurement matrix, and **T2·T3·T4·T6** | `.venv/bin/python scripts/gen_table_T1.py` | all 28 paper cells |
| **F1** the five arms (concept) | `.venv/bin/python scripts/gen_figure_F1.py` | no store — conceptual diagram |
| **F2** the harness (concept) | `.venv/bin/python scripts/gen_figure_F2.py` | no store — conceptual diagram |
| **F3** writer law · **F4** four quadrants · **F5** mechanical-failure collapse | `.venv/bin/python scripts/gen_figures_p1.py` | writes into `documentation/article/experimentation_article/figures/` |
| any single cell's numbers | `.venv/bin/python scripts/cell_status.py <store>` | `.cache/suggestions_<store>` |
| any cell document | `.venv/bin/python scripts/gen_cell_doc.py <store> --out <file.md>` | idem |
| the inventory of every store | `.venv/bin/python scripts/gen_artifact_manifest.py` | all stores |

The 28 per-cell documents in
[`documentation/experiments/final/p1/`](documentation/experiments/final/p1/) each carry the cell's
configuration, its window, its run count, and its caveats. The naming convention encodes all five
coordinates:

```
<CODE>__<dataset>-<engine>__<arm>__<who finds>-<who writes>[__<axis>].md
```

### What is deliberately included but **not** counted

[`documentation/experiments/final/p1/ARTIFACT_MANIFEST.md`](documentation/experiments/final/p1/ARTIFACT_MANIFEST.md)
classifies **every** store in the original repository, including the ones that did **not** go into
the paper and why. Three kinds of store ship here without entering the 2,014:

- **three infeasibility measurements** the paper cites as evidence that a configuration could not be
  run at all (contribution C1-b);
- **`control_monolithic_flash`** — an earlier-regime monolithic control. §4.6 cites three of its
  measurements in the `q38` counter-example, so it ships in order to be checkable. It is **not**
  the paper's `C3` cell, which is `control_monolithic_flash_p1` (`+noplan`). The two differ in plan
  hints and schema linking; the paper says so explicitly at that point.

## 5. What is **not** freely reproducible — and why

We would rather state this than have you discover it.

| | |
|---|---|
| **Cloud cells cost money** | US$ **0.03–0.13 per run**, and they need a DeepSeek API key. The local arms (`raw`, `aided-local`) cost nothing. |
| **One model is gone** | `deepseek-v4-pro` was retired on **2026-09-14**. Stores that name it cannot be re-run; a request today returns Flash under the old name. The paper's cloud results use **`deepseek-v4-flash` only**, accessed 2026-08-23 → 2026-09-11. |
| **The cloud API drifts** | We observed the same configuration produce different outcomes weeks apart. Every cloud A/B in the paper is run **paired**, contemporaneously, for this reason. Local models do not drift. |
| **Databases are large** | ~124 GB across the three instances. Generated, not shipped. |
| **Output is stochastic** | No seed is fixed. Reproducing a cell reproduces a *distribution*, not a run-for-run match. |

## 6. Layout

```
src/                     the pipeline — nodes, engine backends, the S=1 gate
scripts/                 runner, cell_status, the doc/figure/table generators
  campanhas/             the campaign scripts, one per cell family
queries/                 the 21 TPC-DS and 13 JOB queries, verbatim (JSON)
.cache/suggestions_*/    one directory per cell; one JSON per execution record
documentation/
  experiments/final/p1/  29 cell documents + guide + MANIFESTO + campaign history
  article/.../figures/   F3, F4, F5 (PDF for LaTeX, PNG to eyeball)
  fixed_bugs.md          every instrumentation bug found, with its blast radius
```

`documentation/fixed_bugs.md` is worth reading before trusting any number: it records each
measurement bug we found, when it was introduced, which cells it could have touched, and how we
verified that the affected stores were homogeneous.
